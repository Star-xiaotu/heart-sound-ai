## 1. 录音级元数据表（data_manifest/）

**交接：刘文鑫 → 郝静**（同时提交生成脚本）

【计划书已明确】每条原始录音一行，必须包含以下字段：

| 字段名 | 类型 | 含义 | 备注 |
|---|---|---|---|
| `recording_id` | string | **录音唯一 ID** | 全项目主键，任何片段都要能追溯到这里 |
| `subject_id` | string | 受试者 ID | 划分的依据；缺失时需在报告中说明 |
| `subdataset` | string | 数据子库 | 用于分层划分和跨数据源实验 |
| `label` | int | 标签 | 见下方编码约定 |
| `sample_rate` | int | 原始采样率（Hz） | |
| `duration` | float | 时长（秒） | |
| `n_channels` | int | 通道数 | |
| `file_hash` | string | 文件哈希 | 用于查重，建议 SHA-256 |
| `quality_status` | string | 质量状态 | 见下方取值 |
| `exclude_reason` | string | 排除原因 | **被排除的必须填，不能留空** |

建议文件名：`data_manifest/recording_metadata_v1.csv`

### 标签编码【建议稿】

| 值 | 含义 |
|---|---|
| `0` | 正常 |
| `1` | 异常 |

> 数据集原始标签的编码方式以官方说明为准，**必须统一映射到上表**，
> 映射关系要写进元数据生成脚本并在文档中记录。

### 质量状态取值【建议稿】

`ok` / `too_short` / `silent` / `clipped` / `corrupted` / `duplicate` / `label_abnormal`

## 2. 数据划分文件（data_manifest/）

**交接：刘文鑫 → 郝静**

【计划书已明确】交付三个 ID 清单 + 自动交集检查报告 + 生成脚本和随机种子。

【建议稿】文件格式：

```
data_manifest/split_v1/
├── train_ids.txt        # 每行一个 recording_id
├── val_ids.txt
├── test_ids.txt
├── split_config.json    # 生成参数（比例、随机种子、分层字段）
└── intersection_check.md # 交集检查报告
```

`split_config.json` 至少记录：

```json
{
  "version": "v1",
  "split_unit": "subject_id",
  "ratio": { "train": 0.70, "val": 0.15, "test": 0.15 },
  "random_seed": 42,
  "stratify_by": ["label", "subdataset"],
  "generated_at": "<生成时间>",
  "data_version": "<元数据表版本>"
}
```

**硬性要求【计划书已明确】：**
- 受试者交集、原始录音交集**均为零**
- 切片生成后要**再次检查**片段的父录音不存在跨集合现象
- 测试集划分后**封存**，训练期间不得查看测试标签

## 3. 预处理模块接口（src/preprocessing/）

**使用者：刘文鑫（训练端）、李政洪（系统端）**

【计划书已明确】离线实验和在线系统**必须调用同一套预处理代码**，禁止各写一套参数不同的逻辑。

【建议稿】接口形式：

```
输入：音频文件路径（或音频数组 + 采样率）
输出：单通道对数梅尔频谱张量（float）+ 片段元信息
```

片段元信息至少包含【计划书已明确】：

| 字段 | 含义 |
|---|---|
| `recording_id` | 父录音 ID（**可追溯的关键**） |
| `segment_index` | 片内序号 |
| `start_time` / `end_time` | 在父录音中的起止时间 |
| `valid_length` | 真实有效长度（零填充前） |
| `label` | 标签（**推理时为空**） |

**冻结参数【计划书已明确】：**
- 采样率：2000 Hz 或 4000 Hz（通过消融实验确定）
- 窗口：**2 秒**，步长 **1 秒**（50% 重叠）；1 秒窗口作为对照
- 频谱**保存为浮点数组，不转 PNG**
- 归一化与标准化参数**只从训练集估计**

最终参数值在第四阶段确定后，写进 `configs/` 并在本文件更新。

## 4. 模型部署包

**交接：刘文鑫 → 李政洪**

【计划书已明确】必须包含：**模型权重、标准化参数、标签映射、配置、固定样本的期望输出**。

【建议稿】目录形式：

```
checkpoints/<model_version>/
├── model.pth              # 权重
├── model_config.json      # 结构配置（可由配置文件重建模型）
├── norm_params.json       # 标准化参数（mean / std / epsilon）
├── label_mapping.json     # 标签映射 {"0": "正常", "1": "异常"}
├── train_config.json      # 随机种子、轮数、批量大小、学习率
├── model_version.txt      # 版本号与冻结日期
└── golden_samples/        # 固定测试样本 + 期望输出（一致性测试用）
    ├── <样本>.wav
    └── expected_output.json
```

**验收要求【计划书已明确】：** 同一音频经过离线脚本和系统在线推理，得到的**输入张量和预测结果必须一致**。

## 5. 统一推理接口

**主责：李政洪**

【计划书已明确】输出必须包含：**类别、概率、输入质量标记、模型版本、推理耗时**。

【建议稿】字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `label` | int | 0 / 1 |
| `label_name` | string | 正常 / 异常 |
| `probability` | float | 异常概率，0~1 |
| `quality_flag` | string | 输入质量标记 |
| `model_version` | string | **每次加载模型都要记录** |
| `inference_ms` | float | 推理耗时（毫秒） |
| `aggregation_rule` | string | 使用的聚合方法 |
| `threshold` | float | 使用的阈值 |

> 界面**只展示算法能真实计算的内容**。未经验证的患者信息和生理指标不得作为真实结果展示。

## 6. 聚合规则与阈值

**交接：郝静 → 李政洪**

【计划书已明确】**必须以配置文件交付，禁止只在聊天或口头说明。**

【建议稿】`configs/aggregation_v1.json`：

```json
{
  "version": "v1",
  "method": "mean",              // mean | max | topq | vote
  "topq": null,                  // method=topq 时生效
  "threshold": 0.5,
  "threshold_source": "val_set_sensitivity_target",
  "determined_on": "val",
  "determined_at": "<冻结日期>"
}
```

**要求【计划书已明确】：** 聚合方法和阈值**在验证集上确定**，测试前冻结，之后不得再改。

## 8. 版本号规范【建议稿】

统一使用 `主版本.次版本`，例如 `v1.0`、`v1.1`。

| 对象 | 命名位置 | 示例 |
|---|---|---|

**最终归档时【计划书已明确】：** 全组使用**同一版本号**，并同时备份代码、模型、配置、结果、系统和文档，保证答辩现场能离线运行。
